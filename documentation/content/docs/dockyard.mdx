---
title: Dockyard
description: The official Dock images, how to list them, and how to create a Dock from one.
---

Dockyard is the set of official images a Dock can start from. Each image is
built from source in `usedock/docklet`, published with a signature, and verified
by the host before it boots a Dock.

## Images

| Image | Contents | Arch |
|---|---|---|
| `ubuntu-24.04` | Minimal Ubuntu 24.04: systemd, openssh-server, git, curl, python3. The default. | amd64 |
| `node-22` | `ubuntu-24.04` with Node.js 22 | amd64 |
| `python-3.12` | `ubuntu-24.04` with Python 3.12, pip and venv | amd64 |
| `browser` | `ubuntu-24.04` with Chromium and its dependencies | amd64 |

No image has a coding agent baked in. Bring any agent and install it in the
environment setup script (see [Concepts](/concepts)).

## List images

```bash
dock images
```

The API route behind it is `GET /v1/images`. Any authenticated caller can read it.

```json
{
  "ok": true,
  "data": [
    {
      "name": "ubuntu-24.04",
      "description": "Minimal Ubuntu 24.04: systemd, openssh-server, git, curl, python3",
      "arch": ["amd64"],
      "sizeMiB": 1536,
      "contents": "Ubuntu 24.04 with systemd, openssh-server, git, curl and python3",
      "available": true
    }
  ]
}
```

`available` is true when a connected, online host serves the image. Hosts do not
report which images they hold yet, so today only `ubuntu-24.04` shows as
available, and only while at least one host is online.

## Create a Dock from an image

```bash
dock new --image node-22
```

Over the API, send `image` in `POST /v1/docks`. An image that is not in the
catalog is refused with 400 `image_unknown`, and the response lists the valid
names. A catalog image is accepted even when `available` is false; the host that
receives the Dock refuses an image it does not hold.

## Signed artifacts

Every image artifact is signed by the release workflow in `usedock/docklet`, and
the docklet checks the signature and digest before it uses an image.

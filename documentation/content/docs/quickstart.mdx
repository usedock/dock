## Your first dock on your laptop

No account, no server. The `dock` CLI runs docks on your own machine with QEMU
([Local docks](/local-docks)). Local docks need `dock` v0.2.0 or later; the
CLI is early.

Install it. On macOS and Linux:

```sh
curl -fsSL https://usedock.io/install | sh
```

On Windows PowerShell:

```powershell
irm https://usedock.io/install.ps1 | iex
```

Local docks need QEMU and your machine's hardware accelerator (KVM on Linux,
Windows Hypervisor Platform on Windows; macOS is built but not yet tested; arm64 Linux needs `dock` v0.3.0 or later).
`dock doctor` checks and tells you what to fix. On Windows, see
[Windows](/local-docks/windows). On Linux without KVM, the opt-in
[gVisor runtime](/local-docks/gvisor) (`dock` v0.3.5 or later) runs local docks
through Docker instead.

```sh
dock doctor
dock new web                  # downloads the ubuntu-24.04 image the first time
dock exec web -- uname -a
dock ssh web                  # a shell inside the dock
dock stop web                 # powers it off and keeps the disk
dock resume web
dock branch web --name web-2  # copies the stopped disk (no live fork locally)
dock rm web
```

With no API key or URL configured, the CLI uses its built-in `local` context.
Local docks differ from a control plane in a few ways (branching copies a
disk, `dock port` forwards to `127.0.0.1`); see [Local docks](/local-docks).

### Switch to a control plane

When you want shared or always-on docks, point the CLI at a control plane you
host ([Self-hosting](/self-hosting)):

```sh
dock context add home --url https://dock.example.com
dock context use home
dock login                    # prompts for your API key
```

Create the key as described below. Switch back any time with
`dock context use local`. Dock Cloud, a hosted
control plane, is coming soon. The rest of this page uses a control plane.

## Using a control plane

The examples use `https://dock.example.com` for your control plane. Replace it
with your own origin (`DOCK_PUBLIC_URL`; see [Self-hosting](/self-hosting)).
You need at least one host enrolled and online, or creating a Dock fails with 503
`no_host_capacity` (`capacity_exhausted` when no host has room for the size).

## 1. Create an API key

Sign in to the dashboard at your origin, open Developers > API keys, and create
a key. The raw key starts with `dock_` and is shown once.

```bash
export DOCK_URL=https://dock.example.com
export DOCK_API_KEY=dock_...
```

Every protected call takes it as `Authorization: Bearer $DOCK_API_KEY`.

## 2. Find a workspace

Docks belong to a workspace. List your organizations, then the workspaces in
one of them.

```bash
curl -sS "$DOCK_URL/v1/organizations" \
  -H "Authorization: Bearer $DOCK_API_KEY"

curl -sS "$DOCK_URL/v1/organizations/<org-id>/workspaces" \
  -H "Authorization: Bearer $DOCK_API_KEY"
```

## 3. Create a Dock

Only `workspaceId` is required. Size defaults to 2 CPUs, 4096 MiB of memory and
a 20 GiB disk. `name` is optional and unique per workspace. `image` defaults to
`ubuntu-24.04`; the other images are listed in [Dockyard](/dockyard).

Creation takes an `idempotency-key` header, so a retried request returns the
original Dock instead of creating a second one. The call returns once the host
has started the Dock.

```bash
curl -sS -X POST "$DOCK_URL/v1/docks" \
  -H "Authorization: Bearer $DOCK_API_KEY" \
  -H "Content-Type: application/json" \
  -H "idempotency-key: quickstart-1" \
  -d '{"workspaceId":"<workspace-id>","name":"scratch","cpus":2,"memoryMiB":4096,"diskGiB":20}'

curl -sS "$DOCK_URL/v1/docks" -H "Authorization: Bearer $DOCK_API_KEY"
```

The Dock object carries `cpus`, `memoryMiB`, `diskGiB`, `image`, `runtime`, and
`persistentPaths`.

## 4. Run a command

`POST /v1/docks/:id/exec` runs one command in a ready Dock, as the Dock user
under `bash -lc` in `/home/user/work`, and returns its output.

```bash
curl -sS -X POST "$DOCK_URL/v1/docks/<dock-id>/exec" \
  -H "Authorization: Bearer $DOCK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"command":"uname -a && git --version","timeoutSeconds":60}'
```

The result is `{ exitCode, stdout, stderr, durationMs, truncated }`. Each
stream keeps its first 1 MiB (`truncated: true` when clipped). Optional fields:
`env` (variables for this call only, never stored), `cwd` (absolute path), and
`timeoutSeconds` (default 60). A command past its timeout is killed and returns
504 `exec_timeout`; a Dock that is not ready returns 409 `dock_not_running`.

## 5. Stop, resume, branch

`POST /v1/docks/:id/stop` archives the Dock's disk to a Snapshot and releases
its compute. `POST /v1/docks/:id/resume` boots the same Dock from that Snapshot.
`POST /v1/docks/:id/branch` starts a new, independent Dock from it. See
[Docks](/concepts/docks) for the lifecycle.

## Use the CLI or an SDK

The same flow without curl. The CLI keeps the origin and key in a context; the
SDKs read `DOCK_API_KEY` and take the origin as an option or `DOCK_API_URL`.
Dock names are unique per workspace, so these examples use new names next to
the `scratch` Dock from step 3.

```bash
# CLI: see /cli for install
dock context add home --url "$DOCK_URL" --workspace <workspace-id>
dock context use home
echo "$DOCK_API_KEY" | dock login
dock new scratch-cli
dock exec scratch-cli -- uname -a
dock stop scratch-cli && dock resume scratch-cli
dock rm scratch-cli
```

```ts
// TypeScript SDK: see /sdks/typescript for install
import { Dock } from '@usedock/sdk'

const dock = new Dock({ baseUrl: process.env.DOCK_URL }) // reads DOCK_API_KEY
const d = await dock.docks.create({ workspaceId: '<workspace-id>', name: 'scratch-ts' })
const res = await dock.docks.exec(d.id, 'uname -a')
console.log(res.stdout)
await dock.docks.delete(d.id)
```

The [CLI](/cli) installs as a signed release binary. The [SDKs](/sdks)
(TypeScript, Python, Go) are early and not published to package registries yet;
their pages show how to install them from GitHub.

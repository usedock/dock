title: Docks
description: Create, list, update, stop, resume, branch, delete, and run commands in Docks, plus ports, terminal, stats, operations, and disk import and export.
---

A Dock is an isolated Linux machine; see [Docks](/concepts/docks) and
[Runtimes and images](/concepts/runtimes). Routes return the [Dock object](/api/objects#dock).
All routes need an API key or session and org role `member` unless stated.
Shared rules (envelope, errors, idempotency) are in [Conventions](/api).

Size fields share the same limits wherever they appear:

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `cpus` | integer | no | 1 to 64, default 2 | vCPUs. |
| `memoryMiB` | integer | no | 512 to 262144, default 4096 | Memory in MiB. |
| `diskGiB` | integer | no | 1 to 2048, default 20 | Disk in GiB. |

The upper bounds are validation limits; placement also needs a host with room,
or the call fails with `capacity_exhausted` (503).

Lifecycle calls (stop, resume, branch, delete) can also fail with `dock_busy`
(409) while the host is busy with another operation on the same Dock; retry
shortly.

### `POST /v1/docks`

Create a Dock (201) and return it once the host has made it ready.

Auth: API key or session. Role: `member` of the workspace's organization.
Accepts `idempotency-key`.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `workspaceId` | uuid | yes | | Workspace that owns the Dock. |
| `name` | string | no | max 100, unique per workspace | Generated when omitted. |
| `image` | string | no | default `ubuntu-24.04`; a name from the [Dockyard catalog](/dockyard#list-images) | Image to boot from. List names with `GET /v1/images`. |
| `cpus`, `memoryMiB`, `diskGiB` | integer | no | see above | Size. |
| `ttlSeconds` | integer or null | no | 60 to 2592000, default `null` | Seconds after the Dock becomes ready before it stops automatically; `null` disables auto-stop. |
| `environment` | string | no | max 100 | Environment name; the organization default when omitted. |
| `noEnv` | boolean | no | default `false` | Skip the Environment's variables and files. |
| `env` | object of strings | no | at most 100 variables, 64 KB total; names starting with `DOCK_` and platform-reserved names are refused | Extra environment variables for this Dock. |
| `from` | string | no | max 64 | Template name to start from. |
| `setupScript` | string | no | max 65536 | Script run once after the Dock is ready. |

Response: the [Dock object](/api/objects#dock).

An `image` outside the catalog fails with `image_unknown` (400). A catalog image
that no online host serves fails with `image_unavailable` (400); retry later or
pick an available image from `GET /v1/images`.

Errors: `validation_error` (including a size larger than every online host),
`image_unknown`, `image_unavailable`, `dock_not_found` (unknown workspace),
`environment_not_found`, `environment_secrets_admin_only`, `connector_admin_only` (members, when the Dock has connectors or `from` names a Template saved from a Dock with connectors), `template_not_found`,
`template_source_missing`, `dock_name_taken`, `capacity_exhausted`,
`no_host_capacity`, `host_egress_unsupported`, `base_image_unavailable`, `subscription_required`,
`concurrency_exceeded`, `budget_exceeded`, `idempotency_key_reused`,
`idempotency_in_progress`.

### `GET /v1/docks`

List Docks across your organizations.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `filter` (query) | string | no | letters from `r s p t e`, default `r` | State groups: `r` ready, cloning, idle, running; `s` archived; `p` provisioning, provisioned; `t` archiving; `e` error, unreachable. |
| `all` (query) | boolean | no | `true` or `false` | `true` includes every state and ignores `filter`. |

Response: an array of [Dock objects](/api/objects#dock). Errors: `validation_error`.

### `GET /v1/docks/:id`

Read one Dock. Dock-bound keys may call this for their own Dock.

Response: the [Dock object](/api/objects#dock). Errors: `dock_not_found`.

### `PATCH /v1/docks/:id`

Update a Dock. Every field is optional.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `name` | string | no | max 100 | New name, unique per workspace. |
| `ttlSeconds` | integer or null | no | 60 to 2592000 | Auto-stop timer; `null` clears it. |
| `cpus`, `memoryMiB`, `diskGiB` | integer | no | see above | New size. |

A new size can only be set while the Dock is archived; it applies on the next
resume.

Response: the [Dock object](/api/objects#dock). Errors: `validation_error`,
`dock_not_found`, `dock_name_taken`, `conflict` (size changed while the Dock is
not archived, or `diskGiB` below the data it holds).

### `DELETE /v1/docks/:id`

Delete a Dock and its Snapshots (202).

Role: the Dock's creator, or `admin`. Needs `x-confirm-delete: <dock id>`.

Response: `{ "operation": { ... } }`, an [operation](/api/objects#operation).
Errors: `confirm_required`, `dock_not_found`, `dock_delete_forbidden`,
`snapshot_in_use` (a Template boots from one of its Snapshots), `conflict`,
`dock_busy`.

### `POST /v1/docks/:id/stop`

Stop a Dock and save its state as a Snapshot (202). Stopping an archived or
archiving Dock returns its current state.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `force` | boolean | no | | Archive the Dock without capturing a Snapshot; the machine is destroyed and the Dock keeps only its earlier Snapshots. |

In an organization with retention enabled, a stop without `force` deletes the
Dock's data, so it needs the Dock's creator or `admin`.

Response: `{ "id": "...", "state": "archived" }`, or `"archiving"` when a stop is
already under way. Errors: `dock_not_found`, `dock_delete_forbidden`, `conflict`
(the Dock's state cannot stop), `dock_busy`, `service_unavailable` (the final
Snapshot failed; the Dock keeps running and its billing is paused).

### `POST /v1/docks/:id/resume`

Boot an archived Dock from its latest Snapshot (202).

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `ttlSeconds` | integer or null | no | 60 to 2592000 | Auto-stop timer, counted from when the Dock is ready again. A number replaces the stored value, `null` clears auto-stop, and omitting it keeps the stored value. |
| `cpus`, `memoryMiB`, `diskGiB` | integer | no | see above | Size for this boot. |
| `environment` | string | no | max 100 | Environment to bind. |
| `noEnv` | boolean | no | | Skip the Environment. |

Response: `{ "id": "...", "state": "..." }`. Errors: `validation_error`
(including a `ttlSeconds` out of range), `dock_not_found`, `environment_not_found`, `conflict` (the Dock is not archived,
or has no completed Snapshot), `environment_secrets_admin_only`,
`capacity_exhausted`, `no_host_capacity`, `host_egress_unsupported`, `base_image_unavailable`,
`image_unavailable` (no online host serves the Dock's image), `dock_busy`,
`subscription_required`, `concurrency_exceeded`, `budget_exceeded`.

### `POST /v1/docks/:id/branch`

Copy a Dock into a new one (201): the source is captured and the copy starts
from that Snapshot.

Accepts `idempotency-key`.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `name` | string | no | max 100 | Generated when omitted. |
| `image` | string | no | default the source's image | Must equal the source's image; another catalog image fails with `validation_error`. |
| `cpus`, `memoryMiB`, `diskGiB` | integer | no | see above | Size; defaults to the source's. |
| `ttlSeconds` | integer or null | no | 60 to 2592000, default `null` | Auto-stop timer. |
| `environment` | string | no | max 100 | Environment; defaults to the source's. |
| `noEnv` | boolean | no | defaults to the source's | Skip the Environment. |
| `env` | object of strings | no | as for `POST /v1/docks` | Merged over the source's variables. |

Response: the [Dock object](/api/objects#dock). Errors: as for
`POST /v1/docks` (an `image` outside the catalog is `image_unknown`; a different
catalog image is `validation_error`), plus `dock_not_found` and `dock_busy`.

### `POST /v1/docks/:id/exec`

Run one command in a ready Dock and return its bounded output.

Accepts `idempotency-key` (1 to 255 characters); a replay with the same key
returns the first command's result, whatever the body, and never runs it twice. The command runs as the Dock user under `bash -lc`. Not available
on Docks driven by a Run. Rate limits are in [Conventions](/api#rate-limits).

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `command` | string | yes | 1 to 65536 bytes | Shell command. |
| `timeoutSeconds` | integer | no | 1 to 600, default 60; also capped by the deployment | Seconds before the command is killed. |
| `env` | object of strings | no | at most 64 variables, 32 KB total; names match `[A-Za-z_][A-Za-z0-9_]*`, max 128, not reserved | Extra environment for this call only; never stored. |
| `cwd` | string | no | absolute path, max 1024, default `/home/user/work` | Working directory. |

Response:

```json
{ "exitCode": 0, "stdout": "hello\n", "stderr": "", "durationMs": 214, "truncated": false }
```

`stdout` and `stderr` are UTF-8, each clipped to its first 1 MiB, and `truncated`
is `true` when either was clipped. Errors: `validation_error`, `dock_not_found`,
`environment_secrets_admin_only`, `dock_not_running`, `exec_unavailable`,
`exec_timeout`, `exec_busy`, `exec_failed`, `exec_result_expired`,
`rate_limited`.

### `POST /v1/docks/:id/terminal`

Issue a single-use terminal ticket (201). Open the terminal WebSocket at
`GET /v1/docks/:id/terminal?ticket=<ticket>` before it expires.

No body. Response:

```json
{ "ticket": "...", "expiresAt": "2026-01-01T12:00:30.000Z" }
```

The ticket is valid for 30 seconds. A terminal closes after 30 idle minutes or 12
hours. Errors: `dock_not_found`, `environment_secrets_admin_only`,
`dock_not_running`, `exec_unavailable`, `rate_limited`.

### `GET /v1/docks/:id/ports`

List exposed ports. Dock-bound keys may call this for their own Dock.

Response: an array of
`{ "port": 3000, "visibility": "private", "url": "https://...", "createdAt": "..." }`.
`url` is `null` while hosted ports are off. Ports exposed before `visibility`
existed read as `public`. Errors: `dock_not_found`,
`environment_secrets_admin_only`.

### `POST /v1/docks/:id/ports`

Expose a Dock port at a URL (201). Exposing a port again returns the same URL.
Dock-bound keys may call this for their own Dock. A Dock exposes at most 10
ports.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `port` | integer | yes | 1 to 65535; 2222 is reserved | TCP port inside the Dock; services bound to localhost are reachable. |
| `visibility` | string | no | `public` or `private`; default `private` for a new port | `private` needs a credential at the edge, `public` is open to anyone with the URL. Sent for a port that is already exposed, it changes that port's visibility; left out, the port keeps its current one. |

Response: `{ "port": 3000, "visibility": "private", "url": "https://...", "createdAt": "..." }`.
Errors: `validation_error`, `dock_not_found`, `environment_secrets_admin_only`,
`port_limit_reached`, `ports_unavailable`.

A private port answers only requests that carry one of two credentials:

- A port cookie. A browser without one is redirected through the control plane
  (`GET /v1/ports/access`): if the user is signed in and is a member of the
  Dock's organization, they are sent back to the port URL with a 60-second
  token, which the edge trades for an 8-hour `HttpOnly` cookie that is valid for
  that one port URL only. A signed-out user is sent to the dashboard sign-in
  first. Removing the user from the organization, or closing their account, ends
  access on the next request.
- `Authorization: Bearer dock_...` with an API key bound to that Dock. Other
  keys, including your own user keys, are not accepted. Without a credential,
  requests that do not ask for HTML get `401`.

The service in the Dock never sees the port cookie or an `Authorization: Bearer dock_...`
header sent to a private port; its own cookies and other `Authorization` values pass
through. Switch a port to `public` for webhooks or other callers that cannot sign
in.

### `GET /v1/ports/access`

Browser landing for a private port; not called by API clients. Query `host` is
the port hostname and `next` is the path to open after sign-in. Redirects (302)
to the port URL with an exchange token for an organization member, to the
dashboard sign-in when signed out, and returns `404` (`port_not_found`) for
unknown hosts, public ports, or users outside the organization.

### `GET /v1/ports/auth`

Access check the self-host edge proxy calls before it forwards each request to a
port URL; the edge passes the original `Host`, URI, cookie and `Authorization`
header as `X-Forwarded-*` and request headers. Returns `200` to let the request
through, `302` to start sign-in, or `401`; it never returns Dock data.

### `DELETE /v1/docks/:id/ports/:port`

Stop exposing a port. Dock-bound keys may call this for their own Dock.

Response: `{ "deleted": true }`. Errors: `dock_not_found`,
`environment_secrets_admin_only`, `port_not_found`.

### `GET /v1/docks/:id/stats`

Read the Dock's current resource sample and an optional aggregate. Dock-bound
keys may call this for their own Dock.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `window` (query) | string | no | `1h` or `24h` | Adds a `window` aggregate over that period. |

Response:

```json
{
  "dockId": "...",
  "state": "ready",
  "sample": { "dockId": "...", "at": "...", "cpuPercent": 3.2, "memBytes": 0, "memLimit": 0, "diskBytes": 0, "rxBytes": 0, "txBytes": 0, "source": "..." },
  "window": { "window": "1h", "samples": 60, "avg": { "cpuPercent": 2.1, "memBytes": 0, "memLimit": 0, "diskBytes": 0, "rxBytes": 0, "txBytes": 0 }, "peak": { "cpuPercent": 9.8, "memBytes": 0, "memLimit": 0, "diskBytes": 0, "rxBytes": 0, "txBytes": 0 } }
}
```

`sample` is `null` when no sample has arrived yet, and carries a `containers`
array when the Dock reports per-container usage; `window` is present only when
requested. Errors: `validation_error`, `dock_not_found`.

### `GET /v1/operations/:id`

Poll an [operation](/api/objects#operation). Operations belong to the
organization of the thing they changed; ones you cannot see read as not found.

Response: the [operation object](/api/objects#operation). Errors:
`operation_not_found`.

## Import and export

These six routes move a Dock's disk between control planes; the `dock push`
and `dock pull` commands drive them. The walkthrough, with the upload and
download steps, is in [Push and pull](/local-docks/push-pull). The file that
moves is `rootfs.ext4.zst`, the raw ext4 disk compressed with zstd. Only the
disk moves, never memory, so an imported or exported Dock boots fresh. Both
directions need a `microvm` runtime; a `gvisor` Dock cannot be exported.

Imports land only on hosts whose docklet advertises the `verified-imports`
feature, so older docklets never boot a disk they cannot verify. When no online
`microvm` host has it, `POST /v1/docks/import` fails with `runtime_unsupported`
(409) and nothing is uploaded. The check applies on a real fleet
(`RUNTIME_DRIVER=restate`).

### `POST /v1/docks/import`

Start an import (201): reserve an upload for a disk and get the part URLs.

Auth: API key or session. Role: `member` of the workspace's organization. An
organization can hold 5 open imports at once.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `workspaceId` | uuid | yes | | Workspace the Dock is created in. |
| `name` | string | no | max 100, unique per workspace | Generated when omitted. |
| `image` | string | yes | a name from `GET /v1/images` | The Dockyard image the disk was built from. |
| `cpus` | integer | yes | 1 to 64 | vCPUs of the new Dock. |
| `memoryMiB` | integer | yes | 512 to 262144 | Memory in MiB. |
| `diskGiB` | integer | yes | 1 to 2048 | Disk in GiB. |
| `sizeBytes` | integer | yes | at least 1; at most `diskGiB` GiB in bytes | Size of the compressed file. |
| `sha256` | string | yes | 64 lowercase hex characters | sha256 of the compressed file. |

Response: the [Import upload object](/api/objects#import-upload).
Cut the file into `partSize` bytes (the last part may be shorter) and `PUT` the
raw bytes of part `number` to its `url`. Part numbers start at 1. The part size
is at least 16 MiB, and grows for a very large disk so the file stays within
10000 parts. The import expires 24 hours after it starts, together with its
uploaded parts.

Errors: `validation_error` (a malformed body or `sha256`), `image_unknown`,
`dock_not_found` (unknown workspace), `import_too_large` (413: `sizeBytes`
above the `diskGiB` limit, or in `proxy` mode a disk whose part size would
exceed 128 MiB), `runtime_unsupported` (409), `dock_name_taken`,
`import_limit_reached` (429), `environment_secrets_admin_only` (403: a member, when the organization's default Environment passes admins-only secrets),
`import_egress_unsupported` (409: the organization's default Environment has an
egress allowlist and no host that verifies imports can apply it on resume;
upgrade the docklets).

### `PUT /v1/docks/import/:importId/parts/:number`

Upload one part through the control plane. Only used when the import's
`upload.mode` is `proxy`; in `direct` mode it fails with `conflict` (409) and
the part goes to the presigned URL instead.

Auth: API key or session. Only the member who started the import can use it.

The body is the raw part bytes, not JSON.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `importId` (path) | uuid | yes | | Id from the start response. |
| `number` (path) | integer | yes | 1 to the number of parts | Part number. |
| body | bytes | yes | non-empty, at most `partSize` bytes (and at most 128 MiB) | Raw part bytes. |

Response: `{ "number": 1, "etag": "..." }`, with the same value in the `etag`
response header. Keep the etag of every part for the complete call. Uploading a
part again replaces it.

Errors: `import_not_found`, `validation_error` (part number out of range or an
empty body), `part_too_large` (400), `conflict` (the import is no longer
`uploading`, has expired, or is `direct`).

### `POST /v1/docks/import/:importId/complete`

Complete an import (202): join the parts, check the size and create the Dock
from the disk. Only the member who started the import can use it.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `parts` | array of objects | yes | 1 to 10000 items; every part number 1 to N exactly once | Each item is `{ "number": integer, "etag": string }`; `etag` max 200 characters. |

Response: the [Dock object](/api/objects#dock), in the `provisioning` state.
The host checks the sha256 and size when it materializes the disk; a Dock whose
file does not match ends in `error`. Repeating the call for a completed import
returns the same Dock. If no host can take the Dock right now, or the name was
taken meanwhile, the call fails with `no_host_capacity`, `capacity_exhausted`,
`host_egress_unsupported` or `dock_name_taken` and can be repeated without
uploading again. Any other
failure ends the import and removes its uploaded parts; start a new one. The
Dock boots in the background, so a host that refuses the image or base later
leaves the Dock in `error` instead of failing this call.

Errors: `import_not_found`, `validation_error` (the parts are not exactly 1 to N
with an etag, or the size is larger than every online host),
`import_too_large` (413: the assembled object is bigger than the `diskGiB`
disk), `import_checksum_mismatch` (400: the assembled object is not the declared
`sizeBytes`), `conflict` (the import failed, expired or is already being
completed), `environment_secrets_admin_only` (a member, when the organization's
default Environment passes admins-only secrets), `no_host_capacity`,
`capacity_exhausted`, `host_egress_unsupported`, `dock_name_taken`, `subscription_required`,
`concurrency_exceeded`, `budget_exceeded`.

### `POST /v1/docks/:id/export`

Start an export (202): the host takes a full, disk-only snapshot of the Dock,
which keeps running.

Auth: API key or session. Role: the same as opening the Dock. A Dock with
connectors, or with secrets from an admins-only Environment, can be exported
only by its creator or an `admin`.

No body. Response: `{ "exportId": "..." }`. Read it with
`GET /v1/docks/exports/:exportId`.

The Dock is then re-applied, so its gateway tokens and its dock API key rotate
and the copy cannot use them. If they cannot be rotated, the export fails with
`export_failed` instead of publishing a disk with live credentials. A Dock holds
one pending export at a time, and an organization 5 live exports.

Errors: `dock_not_found`, `environment_secrets_admin_only`,
`connector_admin_only`, `zdr_blocks_exports` (403: retention is enabled),
`runtime_unsupported` (409: not a `microvm` Dock), `dock_not_running` (409: the
Dock must be `ready`, `idle` or `running`), `conflict` (an export of this Dock is
already in progress), `export_limit_reached` (429).

### `GET /v1/docks/exports/:exportId`

Read an export and a fresh download URL.

Auth: API key or session. Role: the same as opening the source Dock. When the
source Dock is gone, only the export's creator or an `admin` can read it.

Response: the [Export object](/api/objects#export). Poll until `state` is
`ready` or `failed`. Every call to a ready export issues a new `url`.

Errors: `export_not_found` (unknown, expired, or not yours to read),
`environment_secrets_admin_only`, `connector_admin_only`.

### `GET /v1/docks/exports/:exportId/download`

Stream a ready export through the control plane. This is the route the export's
`url` points to when the object store has no address clients can reach; with a
reachable store, use the presigned `url` directly.

Auth and role: as for reading the export.

| Field | Type | Required | Limits / default | Description |
|---|---|---|---|---|
| `Range` (header) | string | no | one `bytes=start-` or `bytes=start-end` | Resume a download. A malformed header is ignored and the whole file is sent. |

Response: the raw bytes (`application/octet-stream`), 200, or 206 with
`content-range` for a range. Check the file against the export's `sha256`.

Errors: `export_not_found`, `environment_secrets_admin_only`,
`connector_admin_only`, `conflict` (the export is not `ready`),
`range_not_satisfiable` (416, with `Content-Range: bytes */<size>`: start past
the end of the file, or end before start).
